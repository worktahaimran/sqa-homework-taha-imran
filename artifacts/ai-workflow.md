I used Claude in the browser to plan and analyze the app's markup, and Claude Code for the actual implementation. I chose Claude Code over Copilot because the task required multi-file scaffolding and iterative changes, not just simple autocomplete.

It wrote the Playwright scaffolding, the eight specs, the helper functions, and the initial drafts of the README and assertions.md. However, every factual detail about the app came directly from me. I had to reject and rewrite four specific things it generated: its implementation of the Promptfoo grader, a submission checklist it completely invented instead of using the provided one, a default retries:1 setting left in the config, and a README claiming the setup was "verified from a clean clone" when no clean clone had been run.

The Promptfoo issue mattered most. It wired the check to an LLM grader that required an external API key, then offered to document that key as a setup requirement. I rejected that approach. A test that cannot execute immediately does not count as running as part of the suite, and it would fail the five-minute installation gate. I had it rebuild the check as a deterministic assertion instead. That turned out better: no API key, no network calls, runs on any reviewer's machine in seconds.

I captured every application state manually using DevTools and fed them in as strict constraints. This included the test IDs, the exact text of the six pill labels, the stop-button streaming signal, two sample answers, and the specific quirk where the initial load renders a greeting with no pills until the page is reloaded. No AI model could infer that last detail. If I had let the tool guess the initial state, the entire suite would have been flaky from the very first run.
